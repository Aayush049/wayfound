PROBE PROOF FOR MUTANT m66 (EQUIVALENCE PROOF)
==============================================
Mutant ID: m66
Target: Line 126 in firestore.rules (Trip archive rule: allow update: if isSignedIn())
Mutation: Drops isSignedIn() check from trip archive rule.

OBSERVATION & EQUIVALENCE ANALYSIS:
1. The trip archive rule at lines 126-132 enforces:
      allow update: if isSignedIn()
        && resource.data.organizerId == request.auth.uid
        && resource.data.archived == false
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['archived'])
        && request.resource.data.archived == true;

2. When a client is unauthenticated (signed out), request.auth is null in Firebase Security Rules.
3. Accessing request.auth.uid when request.auth is null immediately results in a runtime property access evaluation error in CEL / Common Expression Language.
4. Any evaluation error in Firestore Security Rules causes the boolean condition to evaluate to false (denial of the write operation).
5. Therefore, even when isSignedIn() is dropped by mutant m66:
      resource.data.organizerId == request.auth.uid
   triggers an evaluation error on request.auth.uid for unauthenticated callers, rejecting the write.
6. The test 'Trip archive: signed-out user cannot archive trip: DENIED' uses assertFails(tripRef.update({ archived: true })).
   Because the unauthenticated write is still rejected by the runtime evaluation error on request.auth.uid, assertFails succeeds and the test passes.
7. Dropping isSignedIn() alone is strictly equivalent to the original rule for all possible unauthenticated requests.

PROOF VIA COMBINED MUTANT c11:
Combined mutant c11 removes BOTH:
- isSignedIn()
- resource.data.organizerId == request.auth.uid
leaving only:
      allow update: if resource.data.archived == false
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['archived'])
        && request.resource.data.archived == true;

Under c11:
An unauthenticated caller can successfully archive an active trip.
When 'Trip archive: signed-out user cannot archive trip: DENIED' executes under c11:
assertFails(tripRef.update({ archived: true })) FAILS because the write is allowed.
Thus, combined mutant c11 is KILLED by:
'Trip archive: signed-out user cannot archive trip: DENIED'.

This proves that:
a) The unit test suite actively and sensitively guards against unauthenticated archiving.
b) The survival of m66 in isolation is purely due to redundant authorization defense-in-depth (request.auth.uid error on null request.auth).
c) m66 is a valid SURVIVED_ALLOWLISTED mutant documented in rules_test/mutation/equivalent.json.
