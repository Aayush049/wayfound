3. LEAVE & REMOVE MEMBER AUDIT (`trips/{tripId}` & subcollection `members/{uid}`)
================================================================================

A. LEAVE TRIP (`TripRepository.leaveTrip`)
--------------------------------------------------------------------------------
- Dart Code: `lib/features/trips/data/trip_repository.dart` (`leaveTrip`)
- Atomic Batch Operations:
  1. Update `trips/{tripId}`:
     - `memberIds`: Filtered list removing `userUid`.
     - `memberCount`: `newMemberIds.length`.
  2. Update `trips/{tripId}/members/{userUid}`:
     - `status`: `'left'`.

- Firestore Rule (`match /trips/{tripId}` -> `allow update` & `match /members/{uid}` -> `allow update`):

| Condition / Field | Dart Implementation | Firestore Rule Expectation | Match Status |
|-------------------|---------------------|----------------------------|--------------|
| Auth & Base | `isSignedIn()` | `isSignedIn() && resource.data.archived == false` | MATCH |
| Affected Keys (`trips`) | `['memberIds', 'memberCount']` | `affectedKeys().hasOnly(['memberIds', 'memberCount'])` | MATCH |
| Decrement Count | `newMemberIds.length == resource.data.memberCount - 1` | `request.resource.data.memberCount == resource.data.memberCount - 1` | MATCH |
| Removed User Auth | `userUid == request.auth.uid` | `resource.data.memberIds.removeAll(resource.data.memberIds)[0] == request.auth.uid` | MATCH |
| Member status update | `status: 'left'` | `existsAfter(...) && data.status == 'left'` with affectedKeys `['status']` | MATCH |


B. REMOVE MEMBER (`TripRepository.removeMember`)
--------------------------------------------------------------------------------
- Dart Code: `lib/features/trips/data/trip_repository.dart` (`removeMember`)
- Atomic Batch Operations:
  1. Update `trips/{tripId}`:
     - `memberIds`: Filtered list removing `targetUid`.
     - `memberCount`: `newMemberIds.length`.
  2. Update `trips/{tripId}/members/{targetUid}`:
     - `status`: `'left'`.

- Firestore Rule Validation:
  - Organizer check: `isTripOrganizer(tripId)` validates that the caller is the organizer removing another member (`resource.data.fromUid != request.auth.uid` or target != organizer).
  - Organizer self-removal prevention rule: `!(... == organizerId && ... == request.auth.uid)` correctly ensures organizers cannot leave without transferring ownership (or leave via remove logic).
  - Member doc update: `status: 'left'` with `affectedKeys().hasOnly(['status'])`. All match rules.
